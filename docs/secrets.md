# Secrets map

Where every credential in the stack comes from and which `.env` it goes in.
No values live here. Each service's `.env.example` is the authoritative list of
its variables; this page explains the ones that are easy to confuse and how to
obtain them.

## Third-party credentials

| Credential | Obtain | Goes in |
|---|---|---|
| TMDB API key (v3) | themoviedb.org account -> Settings -> API -> request a v3 key | `torrent-downloader/.env` (sole TMDB-key holder; the orchestrator and bot resolve metadata through it) |
| qBittorrent WebUI API key | Generated by `bin/medialab-qbt-provision.sh` (or paste one from qBittorrent -> Preferences -> WebUI -> API Key). The script seeds the same value into the container's `qBittorrent.conf`. | `torrent-downloader/.env` as `QB_API_KEY`; `QB_HOST=127.0.0.1` since both share gluetun's namespace |
| qBittorrent WebUI admin password | Set once by the provision script, random | `qbittorrent/admin-password` (gitignored), for the operator's browser only; no service uses it |
| VPN provider key | NordVPN: account site -> NordVPN -> Manual setup -> access token, then the `curl` in `gluetun/vpn.env.example` returns the NordLynx private key. File-issuing providers (Mullvad, Proton, AirVPN, IVPN): download a WireGuard config from the provider's site and save it as `gluetun/wg0.conf`. Never the account password; the key is revocable from the provider's dashboard. | `gluetun/vpn.env` (and `gluetun/wg0.conf` with the `compose.wgfile.yml` overlay) |
| Jellyfin API key | Jellyfin dashboard -> Administration -> API Keys | `medialab-jellyfin/.env`, with `JELLYFIN_HOST` pointing at the host from inside the container |
| Discord bot token + guild id | Discord developer portal -> your application -> Bot | `medialab-bot/.env` |
| Discord notify webhook URL (optional) | Discord -> the target channel -> Edit Channel -> Integrations -> Webhooks -> New Webhook -> Copy Webhook URL. Anyone holding the URL can post to that channel, so treat it as a secret. | `medialab-orchestrator/.env` as `DISCORD_NOTIFY_WEBHOOK_URL`; unset means no follow notices |
| Web UI password + cookie secret | Choose any strong password; generate the secret (`python -c "import secrets; print(secrets.token_urlsafe(48))"`). Rotating the secret signs everyone out. | `medialab-web/.env` as `WEB_PASSWORD`, `WEB_SECRET_KEY` |
| Jackett API key (optional) | Only if Jackett is installed; shown top-right of its web UI | `jackett.json` in qBittorrent's `nova3/engines` directory, not in any service `.env`. Not in use on this host. |

## Inter-service keys

Each service protects its API with a static `X-API-Key` you generate (any
strong random string). The caller and callee must hold the same value:

| Caller variable | must equal | Callee variable |
|---|---|---|
| bot `ORCHESTRATOR_API_KEY` | = | orchestrator `API_KEY` |
| web `ORCHESTRATOR_API_KEY` | = | orchestrator `API_KEY` |
| qBittorrent autorun hook `X-API-Key` (written by the provision script into qBittorrent's preferences) | = | orchestrator `API_KEY` |
| orchestrator `TORRENT_DOWNLOADER_API_KEY` | = | torrent-downloader `API_KEY` |
| orchestrator `MEDIALAB_JELLYFIN_API_KEY` | = | medialab-jellyfin `API_KEY` |

These pairs are hand-synced today. The setup wizard
(MickMarch/medialab#23) will generate them from one input.

## VPN

Torrent traffic leaves only through gluetun's tunnel: qBittorrent and
torrent-downloader share its network namespace and have no other route.
torrent-downloader additionally checks qBittorrent's bound interface against
its `VPN_INTERFACES` allowlist (`tun0` inside the namespace) and fails closed,
so a dropped tunnel is a clear `VPN_NOT_BOUND` error rather than a stall. No
VPN account password is ever collected; `gluetun/vpn.env` holds a
provider-issued key or points at a WireGuard config file. Design:
`docs/specs/containerized-stack-vpn.md`.

## Rules

- Every `.env` is gitignored. Never commit a real value.
- Never print a `.env` or `docker compose config` output to a shared terminal;
  it renders secrets in the clear.
- Rotate any key that has been displayed before sharing the project.
