# Spec: custom media libraries

Status: Draft
Issue: MickMarch/medialab#164

## Problem

Every service assumes exactly two libraries on one drive:

- `MediaType` maps one to one onto the `Movies` and `Shows` folders
  (`MEDIA_TYPE_SUBDIRS` in medialab-contracts).
- One host folder, `MEDIA_HOST_DIR`, is mounted at `/media` in the
  orchestrator and qBittorrent. Rename, deletion, staging and `GET /storage`
  all derive their paths from it.
- Setup registers one Jellyfin library per media type. medialab-jellyfin
  finds a library by collection type and returns 409 when there are two of
  the same type.

The household wants more libraries, starting with Kids and Anime. Other
installs will want a different set. A library should be able to live on any
drive, including a removable one, and the storage view should show space
per drive.

## Goal and non-goals

Goal:
- The operator defines libraries. Each has a name, a kind (movies or shows),
  a storage root and a folder.
- A storage root is a host folder on any drive. One install can have
  several.
- Every download is routed to one library:
  - a rule on the library (genre, original language, origin country,
    certification) picks it;
  - the user can change the pick in web, at download or follow time.
- A storage root whose drive is missing is offline. Nothing is lost:
  - no download is routed to it;
  - the follow skips it;
  - Jellyfin keeps the library's items and watch state.
- `GET /storage` groups libraries by drive.
- An existing install upgrades with no file moves. Movies and Shows on
  `MEDIA_HOST_DIR` become the first root and its two libraries.

Non-goals:
- Moving a title that is already placed (for example JUJUTSU KAISEN from
  Shows to Anime) from inside the suite. It is documented as a manual move
  and a rescan. A follow-up issue covers an in-app move.
- Mixed-content Jellyfin libraries. A library holds one kind only.
- Editing libraries from web or the bot. Changing a root changes container
  mounts, so it goes through setup.
- A library picker in the bot (see UI scope in the root `CLAUDE.md`). The
  bot uses the rule's pick and shows the library name in its confirmation.

## Design

### Model

```
StorageRoot   id (slug), host_path (e.g. F:/Media, E:/Anime)
Library       id (slug), name (the Jellyfin library name), kind (movie | show),
              root (StorageRoot.id), folder (e.g. "Kids Movies"), rule (optional),
              default (bool: the fallback for its kind; exactly one per kind)
Rule          genres (any of, TMDB genre names), original_languages (any of),
              origin_countries (any of), max_certification (US rating ladder)
```

On disk, per root:

```
<host_path>/<folder>/...             library content (what Jellyfin indexes)
<host_path>/_incoming/<folder>/...   staging, same drive as the library
<host_path>/.medialab-root           marker; its absence means offline
```

This is today's layout with `MEDIA_HOST_DIR` as the only root, so an
existing install needs no file changes.

### Ownership

| Fact | Owner |
|---|---|
| Roots and libraries | setup's answers file (`.medialab-setup/answers.toml`, non-secret) |
| Rendered library config | orchestrator `.env` `LIBRARIES` (JSON, pydantic-settings), written by setup |
| Container mounts | `docker-compose.libraries.yml`, generated by setup (gitignored), picked up through `COMPOSE_FILE` in the root `.env` |
| `Library`, `StorageRoot`, `Rule`, the certification ladder | medialab-contracts |
| Routing (rule evaluation) | medialab-orchestrator |

### Mounts

Each root is mounted once, at `/storage/<root id>`, into the orchestrator and
qBittorrent. Both containers see the same container paths. Staging and
library folders share a mount, so placing a file is a rename, not a copy.
Two separate bind mounts would make it a cross-device copy, even on one
drive.

### Routing

The orchestrator resolves a library when the job is submitted, not when it
completes. The save path has to be known before the download starts. In
order:

1. An explicit `library_id` on the request. Web sends it after the user
   changes the pick.
2. For a show, the library that already holds that show's folder. A show
   never splits across libraries.
3. For a followed show, the library stored on the follow.
4. The first library of that kind, in config order, whose rule matches the
   title's TMDB details.
5. The default library for that kind.

An offline root drops out at every step. If the resolved library is offline,
the submit fails with `LIBRARY_OFFLINE` and names the library.

TMDB facts: the downloader's details call adds the US certification
(`append_to_response=release_dates` for movies, `content_ratings` for shows).
The orchestrator reads genres, `original_language`, `origin_country` and the
certification from the details it already fetches.

### Changes by service

| Service | Change |
|---|---|
| medialab-contracts | `StorageRoot`, `Library`, `Rule`, the certification ladder, `rule_matches(rule, facts)`. `MEDIA_TYPE_SUBDIRS` stays as the default folder names |
| medialab-orchestrator | `LIBRARIES` config; `library_id` and `save_path` on `pipeline_job` and the job view; routing as above; rename, deletion, staging and scan paths come from the job's library; `GET /libraries` (with online state); a `library_id` field on `POST /download` and the follow; the follow poll skips offline libraries; `GET /storage` by drive |
| torrent-downloader | `POST /download` takes an explicit `save_path` (container path) from the orchestrator in place of deriving it from `media_type`; TMDB details include the certification |
| medialab-jellyfin | Library lookup by name, not by collection type (two `tvshows` libraries are normal now); scan stays path-based |
| medialab-setup | Collect and edit roots and libraries, with Anime and Kids presets; create folders and markers; render `LIBRARIES` and `docker-compose.libraries.yml`; register each library in Jellyfin; migrate `MEDIA_HOST_DIR` into root `main`; offline safety (see below) |
| medialab-web | Library picker, preselected by the rule, on download and follow; library name on job rows; Storage card by drive |
| medialab-bot | Library name in the download confirmation and in `/storage`; no picker |
| root | `COMPOSE_FILE` and the override in `.env.example`; doctor checks each root's staging folders and marker in place of the fixed `Movies Shows` loop |

### Storage by drive

`GET /storage` returns:

```
drives: [
  { drive: "F:", online: true, total_bytes, free_bytes,
    libraries: [ { id, name, size_bytes | null } ] },
  { drive: "E:", online: false, total_bytes: null, free_bytes: null,
    libraries: [ ... ] }
]
```

- Drives are grouped by the host drive of each root's `host_path`. Two
  roots on one drive appear once.
- `size_bytes` comes from a background walk of each library folder,
  cached. It refreshes every `LIBRARY_SIZE_REFRESH_HOURS` and after a job
  places files in that library. `null` means not measured yet.
- Bot and web consumers move to the new shape in the same release batch.

### Offline roots

- **Detection:** the marker file is missing or unreadable. The health poll
  rechecks each root every tick and logs each change.
- **Downloads:** routing skips an offline root. An explicit pick fails with
  `LIBRARY_OFFLINE`. A job in flight whose staging root goes offline
  becomes `FAILED` with a clear `last_error`. The usual retry and
  attention budget applies.
- **Follow:** a show whose library is offline is skipped for that tick and
  is not marked checked.
- **Jellyfin:** setup turns off real-time monitoring for libraries on a
  removable root, and the suite never scans an offline root's path. What
  Jellyfin's own scheduled scan does with a missing path is open question 1.

## Decisions

1. **A storage root is the unit of mounting; a library is a folder under
   one.** The alternative was one mount per library. Rejected: staging and
   library on separate bind mounts turns every placement into a copy, even
   on one drive.
2. **Routing happens at submit.** The alternative was routing at
   completion. Rejected: the save path, and so the drive, is fixed when the
   download starts. Staging on the wrong drive turns the move into a copy.
3. **Rules with an override.** Chosen with the user. Alternatives were
   always picking manually (one more tap per download) and rules only (a
   misroute needs a manual move).
4. **An existing show folder beats the rules.** Without this, a rule edit
   or a TMDB change would split one show across two libraries.
5. **One kind per library.** Jellyfin's mixed libraries handle shows
   poorly. Kids is two libraries, Kids Movies and Kids Shows, which the
   preset creates together.
6. **Setup owns the definition; web shows it read-only.** The alternative
   was editing in web. Rejected: a new root needs a mount, a container
   recreate and a Jellyfin registration. Setup already does all three.
7. **Marker file for online state.** The alternative was "the folder
   exists". Rejected: a bind mount of a missing host path can show up as an
   empty folder. Then an absent drive would look online and empty.
8. **Library sizes are cached, not computed on request.** Walking a large
   library on every `/storage` read would be slow on a gaming PC.

## Open questions

1. What does Jellyfin 12.3's scheduled library scan do when a library path
   is missing? Does it keep the items, or remove them and their watch state?
   This decides whether setup also has to disable a removable library in
   Jellyfin while it is offline. To be tested on the host with a scratch
   library before Approved.
2. Does Docker Desktop start a container whose bind-mount source drive is
   missing, or does `compose up` fail? If it fails, an offline root blocks
   the whole stack. The fix would be mounting a removable root through a
   path that always exists (for example a folder junction), to be decided
   once tested.
3. Should the Anime preset's rule be genre Animation plus original language
   `ja`, or origin country JP? Language catches co-productions that the
   country misses. Proposed: language.

## Test plan

- **medialab-contracts:**
  - `rule_matches` for each field, with any-of semantics and an empty rule;
  - the certification ladder ordering for movies and TV;
  - `Library` validation: exactly one default per kind; unique ids.
- **medialab-orchestrator:**
  - routing order: explicit pick, existing show folder, follow, first
    matching rule, default;
  - an offline root is skipped and an explicit offline pick fails with
    `LIBRARY_OFFLINE`;
  - rename, deletion and scan paths come from the job's library;
  - staging and destination are under one root;
  - a migration gives existing jobs the `main` root and their media type's
    default library;
  - the follow poll skips an offline library without marking it checked;
  - `GET /storage` groups two roots on one drive and reports an offline
    drive with nulls.
- **torrent-downloader:** `POST /download` uses the given `save_path`; the
  details call carries the certification.
- **medialab-jellyfin:** lookup by name with two `tvshows` libraries; an
  unknown name returns 404.
- **medialab-setup:**
  - an existing install migrates to root `main` with Movies and Shows;
  - the presets render the expected libraries;
  - the override and `LIBRARIES` render from the answers;
  - each library is registered once;
  - the marker and staging folders are created.
- **medialab-web, medialab-bot:** the picker preselects the routed
  library; the storage views render drives, libraries and the offline
  state.

## Rollout

1. medialab-contracts: models, the ladder, `rule_matches`. Minor release.
2. torrent-downloader: explicit `save_path`, certification in details.
3. medialab-jellyfin: lookup by name.
4. medialab-orchestrator: config, routing, job columns and migration, paths
   from the library, the storage shape, offline handling.
5. medialab-setup: roots, libraries, presets, rendering, the migration of
   `MEDIA_HOST_DIR`.
6. medialab-web and medialab-bot: the picker, job library names, storage
   by drive.
7. Root: `.env.example`, `COMPOSE_FILE`, doctor, docs
   (`docs/host-setup.md`: adding a drive, and moving an existing title
   between libraries by hand).
8. Deploy with `bin/medialab-setup.sh update`, then add the Kids and Anime
   presets through setup.
